# object 组 · 数量面 / 对象投影

> 本组工具：`query_object_balance` `project_event`
> 工具面真源是 `../../tool-surface.json`；本卡是 agent 侧说明书，不是新能力。

## 能做什么

- `query_object_balance`：查数量余额（库存 / 在途 / 占用），带单位、维度与水位 `as_of_event_id`，并附事件重算对照。`drift` 为真表示物化值与事件重算不一致，以事件为准。
- `project_event`：把**已接受**事件投影到对象数量面；同 (事件, 对象, 维度) 幂等不叠加。未过确认门的事件不得投影。

**什么时候用**：取库存/在途数做对账或履约判断；事件被接受后推进数量面。数量面只回答「有多少件/多少公斤」，不回答「值多少钱」——金额在账本面，两面不要互相代替。

## 不许做什么

- **不许任何形式的余额直写（含「先写物化表再补事件」）**：余额是投影产物，下一次重算会覆盖物化值；先写后补事件会让账实短暂分叉，分叉期间的每次读取都是错的。
- **不许把同维度不同单位（kg 与 pcs）静默相加**：单位冲突必须 `OBJECT_CONFLICT` 拒写；静默相加会得到物理上无意义的余额，且之后无法拆回。
- **不许把 `pending` 拟稿事件投影进数量面**：未过确认门的事件不算事实；投影它会让库存先于事实变化，确认门就不再是事实边界。
- **不许在数量面查金额或用数量替代金额**：数量与金额是两个面。数量不进分录，账本只记金额；混用会让对账两边都对不上。

## 硬纪律

1. **agent 写路径只出 proposal 或拟稿事件**。`project_event` 不是「写余额」的自由入口，它只把已接受事实投影成数量；要产生新数量，先让事件成立（拟稿 + 确认门）。
2. **未知必须显式 `__unknown__`**。事件里对象、单位、维度缺失时，投影无法成立——如实报缺，不要用默认对象或默认单位把投影硬跑过去。
3. **余额不可直写**。这是本组的核心边界：余额由事件确定性重算并带水位；任何调用方直写都会被覆盖，并让 `drift` 恒真。
4. **过账须已审批规则，缺规则挂待补**。本组不产分录，但投影与过账同源于事件：事件缺过账规则时挂待补、账本余额不变，不能拿数量面的数量去反推金额补账。

## 哪类岗位调哪几件

| 岗位 | 可调工具 | 说明 |
|---|---|---|
| inspector（只读巡检） | `query_object_balance` | 看数量、水位与 `drift`；不投影、不修数。 |
| analyst（定性 / 拟稿） | `query_object_balance`、`project_event` | 把已接受事件投影、对 `drift` 定性；不直写余额。 |
| decider（持确认门） | `query_object_balance` | 确认前看数量影响；投影不是确认门，归核对岗执行。 |

投影只接受已接受事件，所以 `project_event` 放在拟稿岗而不是拍板岗；拍板岗要看数量时只读。
