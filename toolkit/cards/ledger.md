# ledger 组 · 账本只读面

> 本组工具：`query_balance` `query_entries`
> 工具面真源是 `../../tool-surface.json`；本卡是 agent 侧说明书，不是新能力。

## 能做什么

- `query_balance`：按科目 / 币种查余额。余额由 `journal_entries` 确定性重算，没有直写余额字段——读到的每个数字都能追回分录。
- `query_entries`：分页查已落账分录，含原币 / 折算、出处、来源引用、时间戳与冲正关联。键集游标分页，响应带 `next_cursor` / `has_more` / `rows_returned`。

**什么时候用**：对账前取账面基准、期末核对、给决策队列准备证据、复核某笔冲正是否成对。读到异常时把证据（分录 + `source_ref`）记下来交给核对岗，不在读取侧「顺手修数」。

## 不许做什么

- **不许期望在这里找到写余额、调账或改分录的工具**：本组两件都是只读；余额派生、分录 append-only。没有写入口是设计，不是缺失。
- **不许把分页结果当全量结论**：`has_more` 为真时没翻完，就不能说「账上只有这些」。把截断当事实是对账里最常见的假阳性来源。
- **不许用账本面查库存 / 在途 / 占用数量**：账本只记金额，数量在 object 组。在账本里找数量只会得到错误的「没有」。
- **不许把 `query_balance` 的数字当可改写对象**：余额是派生值；要让余额变，只能补正确分录并经确认门。

## 硬纪律

1. **agent 写路径只出 proposal 或拟稿事件**。本组只读，读出错也仍然走写路径：更正要么出 proposal，要么提交冲正，不能从读取工具拐进写操作。
2. **未知必须显式 `__unknown__`**。查不到、字段未回填、来源系统没给——都要如实标未知；把空结果说成「余额为零」会让后续计费、额度与对账建立在错误的零上。
3. **余额不可直写**。账本面没有直写余额的入口；任何「先改余额再补分录」的顺序都会在下一次重算时被打回。
4. **过账须已审批规则，缺规则挂待补**。分录是规则的产物；读不到某类事件的分录时，先看 posting 组的待补清单，而不是自己编一条分录补上。
5. **资金类科目禁入（二清红线）**。资金池、代收代付、分账执行不在内核账内；读到相关科目名时应视为越界信号并上报，不得据此推算资金头寸或生成写入建议。

## 哪类岗位调哪几件

| 岗位 | 可调工具 | 说明 |
|---|---|---|
| inspector（只读巡检） | `query_balance`、`query_entries` | 取基准数、查积压与异常，只读不写。 |
| analyst（定性 / 拟稿） | `query_balance`、`query_entries` | 用分录证据支撑差异定性，再决定出不出 proposal。 |
| decider（持确认门） | `query_balance`、`query_entries` | 确认前自查账面影响；读权限不代替确认权限。 |

本组不区分岗位工具集，因为两件都是只读；区别在读完之后的动作归谁。
